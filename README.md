# Oncora Nexus

**Evidence grounded decision support for breast cancer multidisciplinary teams.** Oncora Nexus prepares a case for the tumour board in one place: treatment pathway options distilled from curated guidance, relapse risk from externally validated survival models, a molecular subtype estimate, eligible clinical trials screened criterion by criterion, and a retrieval augmented evidence copilot whose every sentence is checked against the passage it cites. Everything runs on local infrastructure with an open source language model, so no patient information leaves the hospital network.

![Oncora Nexus case workspace](docs/images/case_brief.png)

## Project brief

Breast cancer is the most common cancer in the United Kingdom, with around 56,000 new diagnoses each year, and almost every patient is discussed at a multidisciplinary team meeting before treatment begins. Those meetings are under sustained pressure. A typical breast MDT reviews dozens of cases in a single session, which leaves a few minutes per patient to reconcile pathology, imaging, receptor status, genomic results, prior treatment and patient preference against guidance that changes several times a year. Each new trial result (adjuvant CDK4/6 inhibition, antibody drug conjugates for HER2 low disease, neoadjuvant immunotherapy for triple negative cancer) adds a branch to an already dense decision tree. The cost of missing a branch is real: an eligible patient not offered an effective therapy, or a trial slot that goes unfilled.

Clinical trial enrolment is the clearest symptom. Only a minority of adults with cancer ever enter a trial, and a common reason is not refusal but that nobody checked whether they were eligible. Eligibility criteria are long, free text documents written for regulators rather than clinicians; screening one patient against one protocol takes a research nurse many minutes, and screening against every open study is impossible by hand. Meanwhile the evidence base itself is vast: PubMed indexes hundreds of thousands of breast cancer articles, and the questions asked at the MDT ("is six months of trastuzumab enough?", "can we omit radiotherapy in this 74 year old?") usually have a precise answer buried in a specific trial.

Large language models promise to compress that search, but in oncology an unverified answer is worse than no answer. A fluent sentence that invents a hazard ratio, misattributes a trial population or cites a study that says something different can harm a patient. Oncora Nexus was designed around that constraint. It treats the language model as a writer, never as a source: answers are composed only from retrieved passages, every claim carries a citation, and a verifier checks each sentence's wording and every number against the passage it cites before the answer is shown. The predictive models are validated on an external cohort and compared with the Nottingham Prognostic Index that UK clinicians already trust, and every limitation found in that evaluation is reported in the interface rather than hidden.

The project therefore answers a practical question for a cancer centre: can an MDT preparation tool be built entirely from public data and open models, run on hospital hardware, and still be trustworthy enough to show a consultant? The evaluation below says yes for retrieval, grounding and trial screening, and qualifies it for absolute risk prediction, where historical cohorts make recalibration essential.

## What it does

| Capability | What the clinician sees | How it works |
|---|---|---|
| Tumour board brief | Pathway options grouped by treatment category, each linked to its evidence | 42 declarative rules over a structured patient profile, distilled from 48 curated guideline digests |
| Evidence copilot | A cited answer with each sentence underlined by verification status | Hybrid BM25 and dense retrieval over 13,660 passages, learned reranking, local LLM synthesis, sentence level verification |
| Prognosis | Relapse free survival curve, 3, 5 and 10 year estimates, risk group, NPI, per feature drivers | Penalised Cox model trained on METABRIC, externally validated on GBSG2 |
| Molecular subtype | PAM50 subtype probabilities with an honest reliability note | Multinomial models on routine pathology and on PAM50 gene expression |
| Trial screening | Trials ranked as likely eligible, needs review or excluded, with every verdict traced to a protocol line | Parser that converts free text criteria into 7,068 typed constraints across 999 trials |
| Cohort explorer | Survival by intrinsic subtype and receptor group | Kaplan Meier and log rank analysis on METABRIC (2,509) and TCGA (1,084) |
| Model governance | Every metric, calibration plot, limitation and audit entry | Reports regenerated by one command; append only audit log with no raw patient text |

## Live demo

The interface ships with two engines behind one API contract. When the FastAPI service is reachable it uses the full pipeline with the local language model; when it is not, it loads a 5.7 MB bundle and runs retrieval, reranking, answer composition, verification, prognosis, subtype and trial screening entirely in the visitor's browser. That is what powers the hosted demo, so the demo works with no server and no data leaves the page.

## Data foundation

All data is public and downloaded reproducibly by `scripts/download_data.py`, which verifies every transfer and resumes interrupted downloads.

| Source | Content | Size used | Role |
|---|---|---|---|
| PubMed 200k RCT (Dernoncourt and Lee, 2017) | 195,654 randomised trial abstracts with sentence role labels and PMIDs | 2,988 breast oncology abstracts after filtering, 6,620 passages | Literature evidence |
| NLI4CT (SemEval 2023 Task 7) | 999 breast cancer ClinicalTrials.gov reports and 2,400 expert statements with gold evidence lines | 6,992 passages, 7,068 parsed criteria | Trial evidence, trial screening, verifier evaluation |
| Curated knowledge cards (authored) | 48 digests of NICE, ESMO and ASCO positions and landmark trials, each with references | 48 passages | Guideline grounding and pathway rules |
| METABRIC (cBioPortal) | 2,509 patients, 24 clinical variables, survival, PAM50 labels | 1,812 complete cases for the core model | Survival and subtype development |
| METABRIC expression | Illumina HT 12 matrix, 690 MB streamed and reduced to the 50 PAM50 genes | 1,980 samples by 50 genes | Expression subtype model |
| GBSG2 (German Breast Cancer Study Group) | 686 node positive patients from a randomised trial | 686 | External validation |
| TCGA BRCA PanCancer Atlas | 1,084 patients with curated survival and PAM50 calls | 1,084 | Cohort analytics |

The literature filter screens all 195,654 abstracts and keeps those where breast terms dominate, cancer context is present and lactation studies are excluded; the drop from 3,824 to 2,988 abstracts after adding those two rules removed false positives such as infant feeding trials. For production scale, `scripts/fetch_pubmed.py` pulls any PubMed query through the NCBI Entrez utilities (the default query covers every randomised trial, meta analysis and guideline indexed under Breast Neoplasms), and `scripts/fetch_live_trials.py` pulls currently recruiting studies from the ClinicalTrials.gov API. Both feed the same pipeline without code changes. Licences and provenance are in [docs/data_card.md](docs/data_card.md).

## Methods

### Retrieval augmented generation

**Clinical normalisation.** A single tokenizer, ported line for line to TypeScript for the browser engine, maps British spelling to the American spelling of most abstracts (oestrogen to estrogen, tumour to tumor), folds brand names and abbreviations to generic terms (Herceptin to trastuzumab, TNBC to triple negative breast cancer), maps lay phrases to indexed terminology (arm swelling to lymphedema, lumpectomy to breast conserving surgery), removes stop words and applies a deliberately conservative stemmer.

**Section aware chunking.** Abstracts are split into windows of about 180 words with one sentence of overlap and the abstract headline prepended to each chunk, so a results chunk still knows which trial it belongs to. Trial reports are chunked within each section (eligibility, interventions, results, adverse events) with original line numbers retained, which is what makes line level evidence evaluation possible.

**Hybrid retrieval and learned reranking.** BM25 and a 256 dimension latent semantic encoder each nominate 60 candidates, reciprocal rank fusion combines them, and a logistic regression reranker scores eleven interpretable features: normalised BM25, dense cosine, fusion score, query term coverage, bigram overlap, drug match, subtype and setting match, an intent specific section prior (results and conclusions for efficacy questions, adverse event tables for toxicity questions), source type and evidence strength. A diversity step caps each document at two passages. The reranker is trained on 1,950 synthetic queries and never sees the clinical question sets used for evaluation. A neural encoder such as BGE or MedCPT can replace the latent semantic encoder with one environment variable once weights are cached locally.

**Grounded generation.** The local model receives numbered passages with their evidence level and is instructed to answer only from them, cite every sentence, prefer guideline digests and phase 3 trials, state the population each finding applies to, refuse dosing decisions and say plainly when the evidence does not answer the question. When no model is available, an extractive composer selects verbatim evidence sentences ranked by relevance and section, so the system degrades to a slower to read but faithful brief instead of failing.

**Verification.** Every claim sentence is checked against the passages it cites for lexical support, for numeric fidelity (every number in the sentence must appear in a cited passage, because invented percentages and hazard ratios are the most dangerous error in oncology) and for citation validity. The interface underlines each sentence by status and links each citation to its passage, and a confidence level combines retrieval strength, evidence level and faithfulness.

**Safety.** Before anything is logged or sent to the model, NHS numbers, dates, names, emails, phone numbers, postcodes and hospital identifiers are redacted. Out of scope questions are declined, crisis language returns UK support services, and instruction like text inside retrieved documents is neutralised to resist prompt injection. Details are in [docs/safety.md](docs/safety.md).

### Predictive models

**Prognosis.** Relapse free survival is modelled from eight variables an MDT has after surgery (age, tumour size, grade, positive nodes, ER, PR, menopausal status, endocrine therapy). A ridge penalised Cox model, a random survival forest and gradient boosted survival trees are compared under five fold cross validation, against the Nottingham Prognostic Index, and on GBSG2 as an external cohort. The Cox model is deployed because it is calibrated, explainable per patient and small enough to run in a browser. An extended thirteen variable model adds HER2, chemotherapy, radiotherapy, surgery type and lobular histology for internal comparison.

**Molecular subtype.** A multinomial logistic regression on the 50 PAM50 genes is benchmarked against the nearest centroid method by which PAM50 is applied in practice. A second model predicts subtype from routine pathology alone and is benchmarked against the St Gallen surrogate rules, to quantify how often immunohistochemistry gets the molecular subtype wrong.

**Trial screening.** Each eligibility line is classified as inclusion or exclusion (including negated lines inside inclusion sections) and parsed into typed constraints for age, performance status (with Karnofsky converted to ECOG), HER2, hormone receptor and triple negative status, disease setting, menopausal status, BRCA, brain metastases, pregnancy, cardiac function and prior therapy. Lines that limit or time previous treatment, and laboratory or investigator judgement items, are routed to manual review instead of being guessed. Each criterion receives met, not met or unknown with an explanation, and trials are tiered and ranked by confirmed criteria and relevance.

**Pathway rules.** 42 rules in a declarative JSON file, executed identically by the Python service and the browser engine, propose options such as adjuvant abemaciclib for monarchE style high risk disease, trastuzumab emtansine for residual HER2 positive disease, or omission of radiotherapy in PRIME II style patients. Each rule is labelled standard, consider or caution and links to the knowledge cards that justify it.

## Results

All figures are produced by `python scripts/run_evaluation.py` and stored in `reports/`.

### Retrieval

Mean reciprocal rank at 10 and recall at 5 by retriever. The blind set of 20 questions was written after the lexicon and reranker features were frozen and scored once.

| Retriever | Blind questions R@5 | Blind MRR | Development questions R@5 | Development MRR | PubMed known item MRR |
|---|---|---|---|---|---|
| BM25 | 0.75 | 0.712 | 0.76 | 0.696 | **0.944** |
| Dense (LSA) | 0.60 | 0.389 | 0.56 | 0.415 | 0.675 |
| Hybrid fusion | 0.80 | 0.639 | 0.70 | 0.563 | 0.842 |
| **Hybrid fusion with learned reranker** | **0.95** | **0.777** | **0.84** | **0.770** | 0.921 |
| Browser engine (BM25 with lexical reranker) | 0.85 | 0.721 | 0.82 | 0.720 | 0.943 |

![Retrieval ablation](reports/figures/retrieval_ablation.png)

The learned reranker is the single most valuable retrieval component: on clinician style questions it lifts recall at 5 from 0.80 to 0.95 over plain fusion, because naive fusion lets a weak dense signal demote good lexical matches while the reranker learns how much to trust each signal. Plain BM25 wins the known item test, as it should when queries are sampled from the document itself, which is why that test alone would have been a misleading guide. Mean query latency for the full hybrid pipeline is about 5 ms.

### Grounded answers

Across 70 held out clinical questions the copilot cited a relevant guideline digest in 93 percent of answers, produced no answer containing a number absent from its sources, and passed all five safety probes (out of scope, election, crisis language, embedded identifiers, prompt injection). Faithfulness is 1.00 in extractive mode by construction; the same script scores the local language model with `--mode llm`, and the verifier's behaviour on a fabricated percentage is covered by unit tests.

### Evidence checking on NLI4CT

| Task | Oncora Nexus | Baseline |
|---|---|---|
| Ranking gold evidence lines, mean average precision | **0.88** | 0.72 random order |
| Gold lines in the top three, precision | **0.80** | 0.67 random order |
| Claim verification accuracy (entailment versus contradiction) | 0.57 | 0.50 majority |

The line ranker reliably surfaces the lines that support or refute a statement, which is exactly what the verifier needs to anchor citations. Lexical and numeric signals alone are only modestly better than chance at deciding entailment, because NLI4CT statements turn on arithmetic and comparison. This result is why Oncora Nexus describes its verifier as a guard against unsupported wording and invented numbers, not as proof that an answer is correct.

### Prognosis

| Model | C index, METABRIC five fold | C index, GBSG2 external | Integrated Brier score, external |
|---|---|---|---|
| **Cox proportional hazards (deployed)** | 0.650 ± 0.025 | **0.669** | **0.159** |
| Random survival forest | 0.651 ± 0.027 | 0.677 | 0.169 |
| Gradient boosted survival | 0.651 ± 0.021 | 0.673 | 0.160 |
| Nottingham Prognostic Index | 0.641 ± 0.022 | 0.659 | not applicable |

![Discrimination](reports/figures/discrimination.png)

![Risk groups](reports/figures/survival_risk_groups.png)

![Calibration](reports/figures/calibration.png)

Three findings matter for deployment. First, the model adds a consistent but modest gain over NPI (0.669 against 0.659 externally, and 0.666 against 0.641 in sample on node positive METABRIC patients), so its value lies in individualised curves and explanations more than in better ranking. Second, the tree ensembles do not beat the Cox model on calibration, which justifies deploying the interpretable model. Third, calibration is excellent internally but optimistic on GBSG2, where observed five year relapse free survival sits 12 to 17 points below prediction in every risk quintile. Discrimination transfers between populations; absolute risk does not. The interface therefore states that estimates must be reconciled with PREDICT Breast, and the model card recommends local recalibration before any clinical use. Positive nodes (hazard ratio 1.64 per log unit), grade (1.22 per grade) and tumour size (1.12 per centimetre) dominate, matching both the permutation importance of the forest and the structure of NPI.

![Hazard ratios](reports/figures/hazard_ratios.png)

### Molecular subtype

| Model, five fold cross validation | Accuracy | Macro F1 | Cohen kappa |
|---|---|---|---|
| **PAM50 expression, logistic regression** | **0.77** | **0.74** | **0.71** |
| PAM50 expression, nearest centroid | 0.71 | 0.65 | 0.63 |
| Routine pathology, logistic regression | 0.46 | 0.42 | 0.32 |
| St Gallen surrogate rules | 0.50 | 0.37 | 0.34 |

![Subtype confusion](reports/figures/subtype_confusion.png)

A compact expression model reproduces the reference PAM50 call well, but routine pathology recovers the molecular subtype for fewer than half of patients, confusing Luminal A, Luminal B and Normal like tumours most often. For an MDT this is an actionable message: when the surrogate probabilities are close, a genomic assay is the test most likely to change the label. Subtype also carries strong prognostic signal in METABRIC, with ten year relapse free survival ranging from 73 percent for Luminal A to 49 percent for HER2 enriched disease (log rank p below 0.000001).

![Subtype survival](reports/figures/subtype_survival.png)

### Trial screening

The parser extracted 7,068 typed constraints from 999 protocols (about seven per trial), led by disease setting, prior therapy, pregnancy, performance status and HER2. A further 8,730 lines were recognised as laboratory, consent or investigator judgement items and routed to manual review rather than guessed. For a postmenopausal woman with node positive luminal disease, screening narrows 999 protocols to 176 likely eligible and 84 needing review in a few milliseconds, with every verdict traceable to its protocol line.

## Key insights

* **Reranking, not embedding, is where retrieval quality is won** on small clinical corpora. An eleven feature logistic regression added 15 points of recall at 5 on blind questions, more than switching retrievers.
* **Verification has to include numbers.** Lexical overlap catches unsupported wording, but the dangerous oncology failure is a plausible invented percentage; numeric fidelity checks make that failure visible in the interface.
* **External validation changed the product.** Without GBSG2 the survival model would have looked well calibrated; with it, the interface now shows absolute risk with an explicit recalibration warning.
* **Immunohistochemistry is a weak proxy for molecular subtype**, which is a direct argument for funding genomic assays where the surrogate is uncertain.
* **Most eligibility text cannot and should not be automated.** Structured criteria remove most ineligible trials instantly, but the honest design hands laboratory thresholds back to the research team.

## Running it

**Requirements:** Python 3.11 or later, Node 20 or later, about 2 GB of disk, and optionally [Ollama](https://ollama.com) for language model synthesis.

```bash
git clone https://github.com/ANTHONY-CHINEDU-ECHEM/OncoraNexus.git
cd OncoraNexus
make install        # Python and web dependencies
make all            # download data, build index, train, evaluate, export demo, build interface (about 15 minutes)
ollama pull llama3.1:8b   # optional; any Ollama model works via ONCORA_LLM_MODEL
make serve          # API and interface on http://localhost:8000, API docs on /docs
```

Individual stages: `make data`, `make index`, `make train`, `make evaluate`, `make demo`, `make web`, `make test`. Interface development with hot reload: `cd frontend && npm run dev` (proxies `/api` to port 8000). Force the browser engine at any time with `?engine=browser`.

**Docker with a local model:**

```bash
docker compose -f deploy/compose.yml up --build
```

**Configuration** uses environment variables prefixed `ONCORA_`: `LLM_MODEL`, `OLLAMA_URL`, `LLM_PROVIDER` (ollama or extractive), `EMBEDDINGS` (lsa or sentence_transformers), `FINAL_K`, `CORS_ORIGINS`, `AUDIT_DB`. See [docs/deployment.md](docs/deployment.md) for Hugging Face Spaces, GitHub Pages and hospital network deployment.

## Limitations and responsible use

Oncora Nexus is a research and portfolio system, not a medical device. It has not been clinically validated and must not be used to make treatment decisions. The literature corpus ends in 2017, so recent trials are represented through the curated digests rather than their abstracts, and those digests must be checked against current guidance. The survival model reflects patients treated between 1977 and 2005 and overestimates relapse free survival on an external cohort. Trial screening covers structured criteria only and uses completed trials for demonstration. Retrieval still misses some paraphrased questions; for example "is one week of radiotherapy as good as three weeks?" does not retrieve the fractionation digest, a documented failure kept in the evaluation set. The full model card is in [docs/model_card.md](docs/model_card.md).

## Roadmap

* Neural dense retrieval with MedCPT and a cross encoder reranker, evaluated against the same blind set
